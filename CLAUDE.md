# oneD FAQ + น้องดี — instructions for Claude Code

Read `HANDOFF.md` first: it has the history, decisions, open questions and the next steps.

## What this repo is

- **oneD** is a Thai video streaming service (GMM Grammy / one31). Product owner: Komsith (Tong), PM.
- **FAQ page**: one bilingual file (Thai + English, TH | EN switch). Deployed as both `faq-th.html` and `faq-en.html` on `assets.oned.net/doc/`.
- **Support form**: `support.oned.net`, posts to `/submit` (backend not in this repo).
- **น้องดี (Nong Dee)**: AI assistant on the FAQ page. Chat API = AWS Lambda + API Gateway (SAM), calling the Claude API. Answers **only** from the FAQ.

## Layout

| Path | What |
| --- | --- |
| `src/faq.json` | **The FAQ** (source of truth for the page, `GET /faq` and น้องดี): TH + EN, ids, categories, popular, answers as blocks |
| `src/handler.mjs` | API: `GET /faq`, `POST /chat`, `POST /feedback` |
| `src/prompt.mjs` | น้องดี's rules + `ISSUES` (support-form issue values) + verifier rules |
| `src/grounding.mjs` | FAQ-only guardrail (runs on every reply) |
| `src/faq.mjs` | Loads `faq.json`: `faqDocument(lang)` for `GET /faq`, `loadFaq()` = Thai plain text for น้องดี |
| `src/faq-format.mjs` | Answer block format (blocks ↔ page HTML, plain text) and `validate()` |
| `scripts/build-faq.mjs` | Writes `faq.json` into the page's question lists (`--check` to verify) |
| `openapi.yaml` | API spec for the apps (`/faq`, `/chat`, `/feedback`; Firebase bearer auth planned) |
| `template.yaml` | SAM stack (HTTP API, Secrets Manager key, throttling, 90-day logs, `Verify` on) |
| `web/faq-th-beta.html`, `web/faq-en-beta.html` | The FAQ page (identical files) with the widget tag. Question lists are generated: don't hand-edit between the `faq:th` / `faq:en` markers |
| `web/nongdee.js` | Chat widget (TH/EN UI, `data-endpoint="demo"` = no-AI demo mode) |
| `web/support-index.html` | Support form (reads `?issue=`, `?lang=`, `onedSupportPrefill()`) |
| `preview/`, `index.html` | GitHub Pages preview, generated by `scripts/build-preview.mjs` — don't hand-edit `preview/` |
| `test/local-test.mjs` | `npm test` — fake Claude API, 31 tests incl. 14 guardrail and 7 FAQ-data tests |
| `prototype/` | Reference only: the in-browser version used in the Claude artifact prototype |

## Commands

```bash
npm install
node scripts/build-faq.mjs        # after any change in src/faq.json
npm test                          # must stay green
node scripts/build-preview.mjs    # after any change in web/, then commit preview/ too
sam build && sam deploy           # deploy (see README); never commit samconfig.toml or keys
```

## Rules — keep these

**Content**
- **Thai is the source of truth.** English is translated from the Thai, never the other way. The latest source document is the Thai "FAQ on oneD WebApp TH Version 2.0" (Nov 2026).
- The FAQ lives in `src/faq.json`. Each entry has `th` and `en`, sharing one **id, category and popular flag**. Old ids are deep-linked from the app and the support form: never rename or drop one without a redirect.
- Use the app's real button names as `{"type":"ui"}` inlines (rendered as `<span class="ui">`). English labels for new 2.0 screens are unconfirmed (see HANDOFF).
- No facts that aren't in the source document (no invented prices, numbers, steps).

**น้องดี**
- Answers only from the FAQ. Never weaken `src/grounding.mjs` or the prompt rules to make an answer pass; fix the FAQ or the test instead.
- Thai voice: warm, polite young woman, ends statements with ค่ะ and questions with คะ, never ครับ, calls herself น้องดี, user = คุณ. English: "Nong Dee", friendly and brief.
- Replies follow the user's language; the widget's interface follows `<html lang>`.
- `ISSUES` in `src/prompt.mjs` must match the support form's `<option value>`s exactly (they're the backend contract), and `SupportIssue` in `openapi.yaml` (tested).
- The Anthropic API key lives only in Secrets Manager / the Lambda. Never in the page, the app, or the repo. Repo is **public**.
- Mask personal data (email, phone, card numbers) before anything reaches the model or logs.

**Support form**
- Field names and option values are the `/submit` contract: `loginType, email, tel, appVersion, device, model, issue, detail, confirm`. Don't change them without the backend team.
- Personal data never goes in URLs (use `onedSupportPrefill()` for email/phone).

**UI**
- Dark theme, brand pink `#f20b7e`, font Prompt. Mobile-first: inputs 16px (no iOS zoom), touch targets ≥ 44px (TH | EN pills 36px), no sideways scroll at 320px.
- Pages run inside the oneD app's web view (WKWebView / Android WebView): no `target="_blank"`, test there.
- When `nongdee.js` changes, version its URL (`?v=`) so devices don't keep an old copy.

**API for the apps**
- Apps are native **Swift (iOS) and Kotlin (Android)**; TV apps are out of scope. Users sign in with **Firebase Auth**.
- Keep `openapi.yaml` in step with `src/handler.mjs`. `GET /faq` is public; `/chat` and `/feedback` will take a Firebase ID token (not enforced yet).

**Git**
- Commit to `main` with clear messages; the user reviews on GitHub. Run `npm test` and rebuild `preview/` before committing.
